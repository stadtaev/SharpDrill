# Coverage

What SharpDrill models, and what it does not. The claim is narrow on purpose: **which explicit `throw`s in your source
can reach an entry point, and what catches them**. Inside that claim, anything undecided is reported; outside it,
nothing is guessed.

## Inputs

- Restored SDK-style C# projects and solutions, one configuration and framework per project, loaded through the .NET SDK's MSBuild (no Visual Studio). The CLI restores when packages are missing; the library does not.
- Code generated by source generators is included (`--exclude-generated` drops it). Code generated only during a build is missing until you build; compile errors are reported.
- Test projects are skipped by default (`--include-tests`). Non-C# projects are reported as not loaded.

## Entry points

- **Controller actions:** public instance, non-generic methods on non-abstract, non-generic types deriving from `ControllerBase` or carrying `[Controller]`; `[NonAction]`/`[NonController]` (inherited) exclude. Inherited actions from referenced assemblies and minimal APIs are not entry points; minimal API registrations are reported.
- **Main:** a static `Main` of a compiler-accepted shape, or top-level statements (`Program.<Main>$`).
- **Library public API:** for a project with neither, that no loaded project references: public methods, constructors and accessors of public types.

## Calls

| Followed | Boundary (recorded, not followed) |
| --- | --- |
| Invocations, construction, constructors, accessors, operators, conversions, extension methods | Library and framework code (no source body): the end of the claim, never Unknown |
| Local functions and lambdas, as bodies of their own | Delegates, `dynamic`, function pointers, calls that do not compile |
| Field/property initializers, as code of the constructors that run them | Interface/virtual calls with no implementation in source |
| Interface/virtual calls into source implementations, marked as assumed (`--declared-only` stops) | `await` of a task held in a property or parameter |
| Implicit `foreach`/`using` calls, bound through the receiver type | |

Implementations come from source types' interface maps and overrides. DI registrations are not read, so a step into an
implementation is a possibility; a proven direct path to the same throw is preferred.

## Exceptions

- **Origins:** `throw`, throw expressions and rethrows. `throw new E()` has an exact type; `throw e` only its static type ("or a subclass").
- **Catches** apply only to a `try` around the throw or the call. What a handler does comes from its control flow: every exit leaves normally (*handles*), rethrows (*rethrows*), some of each (*may rethrow*, followed further), or throws something else (*replaces*; the new throw is an origin of its own). A filter or a narrow catch of a base-typed exception is a *possible* catch, followed past.
- **Miscaught** only when every clause definitely does not match the type at that point.
- **async:** awaited tasks propagate. The BCL `Task` API is modelled: `await`, `GetAwaiter().GetResult()`, `ConfigureAwait`, `Task.WhenAll(a, b)`, `Task.WhenAny` (observes nothing), `Task.Run`. A task in a private or readonly field surfaces at the `await` of that field when every write is a provable call.
- **async void:** what leaves it ends the process (`Crashes`, SD0005); no `try` around the call catches it.
- **Global handlers:** `UseExceptionHandler`, `UseDeveloperExceptionPage` and global MVC exception filters registered in the action's project or a project referencing it. This is registration evidence, not middleware order or environment conditions; `AddExceptionHandler` alone handles nothing; attribute filters are not modelled.
- **Third-party calls** (`--third-party`): every call into an assembly no .NET reference pack supplies is an origin; any catch on the way wraps it, global handlers do not. Logging (Serilog, NLog, log4net) and `Microsoft.Extensions.*` except Caching are left out.
- **Recursion** is followed, not uncertain.

## Not followed (reported, with a place)

An interface or virtual call without a source implementation; a task that is never awaited; a `finally` that may throw;
an exception leaving an iterator (it surfaces where the sequence is enumerated); async iterators and custom awaitables;
`Task.WhenAll` of a collection; `.Result`/`.Wait()` on a stored task; methods without a body; code that does not compile.

## Not modelled

- Exceptions thrown inside library code and implicit ones (null dereference, overflow, framework validation). No finding does not prove nothing is thrown.
- Branch feasibility: every branch is assumed reachable.
- Which implementation DI picks, middleware order, endpoint routing.

## Projects

`<ProjectReference>` items and evaluated `TargetFramework`, `Nullable`, `TreatWarningsAsErrors`, `WarningsAsErrors`
(including inherited `Directory.Build.props`), and compiler warning/error counts after severity options (analyzer and
NuGet warnings excluded). References outside the loaded workspace are listed as unloaded.
